# Known Issues

## General

- Источники могут менять HTML, JS, API shape и внутренние URL без предупреждения.
- Часть полей зависит от конкретной сети и доступна только в режиме best-effort.
- Если значение отсутствует, противоречит другим сигналам или восстанавливается только спекулятивно, проект сохраняет `None` / `null`.
- Первый полный запуск по новому snapshot не является бизнес-diff: он только инициализирует baseline.

## Monetka

- Некоторые city, pagination и detail pages у Монетки могут возвращать ожидаемый HTTP `404`.
- Такие `404` не считаются parser-level failure, если parser обработал их локально и продолжил сбор.
- Обработанные ожидаемые Monetka `404` логируются как `WARNING`, а не как `ERROR`, чтобы успешный run не выглядел аварийным.
- Если detail page недоступна, проект может сохранить частичную запись из city list, но не выдумывает отсутствующие поля.
- Если на detail page нет store-specific телефона, поле `phone` остается `null`; общий телефон сайта из футера не публикуется как телефон магазина.
- Geography у Monetka confidence-based. Надежными считаются явные detail-поля `Город` / `Регион`, structured data и согласованный видимый crawl context.
- Слабые сигналы Monetka, например `detail` title, breadcrumb-only hints, city page path и технические URL segment-ы вроде `shops_map/ekb/...`, не публикуются как факт.
- Если reliable и weak сигналы конфликтуют или detail/city pages противоречат друг другу без достаточного основания, `city` и/или `region` остаются `None`.

## Maria-Ra

- `region` часто отсутствует или задан только косвенно; parser заполняет его только из явных source-полей или явно указанного региона в адресной строке.
- `city` иногда можно извлечь только из адреса; если в адресе нет надежного признака населенного пункта, поле остается `None`.
- `store_format` и `status` заполняются только если источник явно их отдает; иначе сохраняются как `None`.
- Источник может содержать дублирующие карточки одной и той же точки с одинаковыми координатами, но разным текстом адреса/режима работы. Parser канонизирует такие записи по `stable_key` и логирует конфликт.

## KB

- API может отдавать частичные координаты или неполный metadata payload.
- Если у записи есть только одна координата, проект сохраняет доступную координату и оставляет вторую как `None`, не достраивая пару искусственно.

## Diff And Baseline

- Корректный бизнес-diff появляется начиная со второго полного запуска по тому же snapshot baseline.
- `added`, `removed` и `changed` интерпретируются только в контексте сравнения двух полных snapshot-срезов.
