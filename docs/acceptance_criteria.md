# Acceptance Criteria — Store Parsers Project

Проект считается завершённым, если выполняются следующие условия.

## 1. Парсеры

В проекте реализованы 3 независимых парсера:

- Красное&Белое
- Монетка
- Мария-Ра

Каждый парсер должен:

- получать данные о магазинах с официального сайта
- корректно обрабатывать ошибки сети
- возвращать данные в единой структуре

Обязательные поля записи магазина:

- network
- region
- city
- address
- work_time
- latitude
- longitude
- source_url
- collected_at

Если какие-то поля недоступны на сайте — они должны быть None.

---

## 2. Нормализация данных

Все парсеры должны возвращать данные в **единой схеме**.

Требования:

- одинаковые названия полей
- одинаковые типы данных
- удаление мусора из адресов
- корректная обработка пустых значений

---

## 3. Excel отчёт

Проект должен генерировать Excel файл `stores.xlsx`.

Файл должен содержать листы:

### 1. Актуальные данные
Полный список магазинов.

### 2. Изменения
Содержит изменения относительно предыдущего запуска:

- added
- removed
- changed

### 3. Статистика
Количество магазинов по сетям.

---

## 4. Diff механизм

Система должна:

- сохранять предыдущий снапшот
- сравнивать его с новым
- корректно определять:
  - новые магазины
  - удалённые
  - изменённые

Магазины должны сопоставляться по стабильному ключу.

---

## 5. CLI интерфейс

Проект должен запускаться через CLI.

Команды:

run — запуск всех парсеров

run --network <name> — запуск одного парсера

---

## 6. Логирование

Должны существовать лог-файлы.

Логи должны содержать:

- начало запуска
- количество собранных магазинов
- ошибки
- время выполнения

---

## 7. Тесты

Проект должен содержать тесты.

Минимум:

- тест модели данных
- тест diff механизма
- тест Excel генерации

Все тесты должны успешно проходить.

---

## 8. Документация

README.md должен содержать:

- описание проекта
- установку
- запуск
- структуру проекта
- ограничения парсинга

---

## 9. Чистота репозитория

В репозитории **не должно быть**:

- .venv
- logs
- output
- временных файлов
- системных файлов IDE

Должен быть `.gitignore`.
