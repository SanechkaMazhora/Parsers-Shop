Системный анализ веб-ресурса торговой сети «Монетка»

1. Общая информация о ресурсе

Официальный сайт торговой сети:
https://www.monetka.ru/

На сайте присутствует раздел «Карта магазинов».

В ходе анализа установлено, что структура страниц магазинов
организована по регионам, городам и отдельным магазинам.


2. Анализ механизма получения данных

В ходе анализа страницы карты магазинов установлено, что сайт
содержит отдельные страницы для регионов и городов.

Страница вида:
https://www.monetka.ru/urfo/shops_map

используется для выбора региона и города.

При анализе сетевых запросов было установлено, что сайт не использует
явный REST API для передачи данных о магазинах на страницах отдельных
торговых точек. Основные сведения о магазине отображаются непосредственно
в HTML-коде страницы.


3. Анализ страницы карты магазинов

При анализе сетевых запросов во вкладке Network → Fetch/XHR
был обнаружен запрос list.

Ответ данного запроса содержит HTML-код со списком городов
и ссылками на страницы магазинов.

Примеры ссылок:
- /orenburgskaya-oblasty/shops_map/abdulino
- /orenburgskaya-oblasty/shops_map/aleksandrovka
- /urfo/shops_map/asbest
- /urfo/shops_map/artyomovsk

Таким образом, для каждого города существует отдельная
страница карты магазинов.

Также был исследован запрос department/. Установлено,
что данный запрос не связан с загрузкой данных о магазинах.
Он возвращает HTML-код формы обратной связи, включая
служебные поля формы, список подразделений, поля выбора
региона, города и адреса магазина, а также CAPTCHA формы.

Вывод: запрос department/ является служебным
и не используется для получения данных о магазинах на карте.

Дополнительно был выявлен endpoint:
/feedback/shops

При прямом обращении к данному endpoint без параметров сервер
возвращает ответ в формате JSON:

{"data":[]}

Это указывает на существование дополнительного служебного механизма,
вероятно связанного с формой обратной связи. Однако в ходе анализа
страниц карты магазинов данный endpoint не использовался как основной
источник данных о торговых точках.


4. Получение данных о магазинах

В ходе анализа страниц отдельных магазинов установлено,
что сведения о торговой точке отображаются непосредственно
в HTML-коде страницы.

Например, на странице вида:
https://www.monetka.ru/shops_map/ekb/1194

отображаются следующие сведения:
- адрес магазина
- почтовый адрес
- формат магазина
- режим работы

Анализ сетевых запросов показал, что отдельный API-запрос,
содержащий данные магазина, не выполняется. Информация
передаётся сервером непосредственно в HTML страницы.

Таким образом, основной способ получения данных о магазинах
заключается в последовательном обходе HTML-страниц магазинов.


5. Извлекаемые данные

В результате анализа установлено, что со страницы магазина
могут быть извлечены следующие данные:

- адрес магазина
- почтовый адрес
- формат магазина
- режим работы
- наименование населённого пункта

Координаты торговой точки на текущем этапе анализа
в исходном HTML-коде страницы явно не обнаружены.


6. Анализ заголовков HTTP-запросов

В ходе анализа сетевых запросов страницы магазина во вкладке
Network → Fetch/XHR не были обнаружены отдельные API-запросы,
возвращающие данные о торговых точках.

Обнаруженные запросы носили служебный характер и не содержали
целевой информации о магазине.

Это позволяет сделать вывод, что основная информация о магазине
передаётся непосредственно в HTML-коде страницы.


7. Особенности работы сайта

В ходе анализа были выявлены следующие особенности:

- на сайте используется интерактивная карта на базе Яндекс.Карт;
- для каждого города существует отдельная страница карты магазинов;
- для отдельных торговых точек используются отдельные страницы магазинов;
- список городов возвращается в HTML-виде;
- данные о магазине отображаются непосредственно на странице;
- отдельный API для получения сведений о магазине в ходе анализа
  не был обнаружен.


8. Анализ механизмов защиты

В ходе анализа работы сайта не были обнаружены следующие
механизмы защиты, препятствующие просмотру данных о магазинах:

- обязательная авторизация;
- CAPTCHA при просмотре страниц магазинов;
- ограничения доступа к страницам магазинов.

CAPTCHA была обнаружена только в HTML-коде формы обратной связи,
что не относится непосредственно к механизму отображения магазинов.


9. Предлагаемая стратегия реализации парсера

На основании проведённого системного анализа предлагается
следующая стратегия реализации парсера торговой сети «Монетка»:

1. Открыть страницу списка регионов и городов.
2. Извлечь из HTML ссылки на страницы городов.
3. Последовательно переходить на страницы городов.
4. Извлекать ссылки на отдельные страницы магазинов.
5. Переходить на страницу каждого магазина.
6. Из HTML-кода страницы извлекать сведения о магазине.
7. Сохранять полученные данные в итоговую структуру данных.

Для реализации парсера целесообразно использовать язык
программирования Python и библиотеки requests и BeautifulSoup.

Использование браузерной автоматизации на текущем этапе
не является обязательным, так как основные данные доступны
непосредственно в HTML-коде страниц.


10. Вывод

В результате системного анализа веб-ресурса торговой сети
«Монетка» установлено, что сайт использует структуру отдельных
страниц магазинов по регионам, городам и конкретным торговым точкам.

Список городов доступен через HTML-код страницы выбора региона,
а сведения о конкретных магазинах отображаются непосредственно
на страницах отдельных магазинов.

В ходе анализа не был выявлен отдельный API-запрос, через который
передаются данные о магазинах. Основной способ получения данных —
извлечение информации из HTML-кода страниц магазинов.

Таким образом, реализация парсера сети «Монетка» может быть
выполнена посредством последовательного обхода страниц городов
и магазинов с извлечением данных из HTML-кода.
