# Анализ источника: Мария-Ра

## 1. Источник данных

Парсер использует официальный сайт сети `Мария-Ра` и работает со страницей карты магазинов.

URL, которые явно видны в коде:

- базовый URL по умолчанию: `https://www.maria-ra.ru`
- карта магазинов: `https://www.maria-ra.ru/o-kompanii/karta-seti/`

Эти адреса могут быть переопределены через:

- `STORE_PARSER_MARIA_RA_BASE_URL`
- `STORE_PARSER_MARIA_RA_MAP_URL`

## 2. Формат данных

В текущей реализации парсер реально использует или пытается использовать несколько форматов данных:

- HTML страницы карты
- встроенный JavaScript в `script`
- внешние JavaScript-файлы, подключенные со страницы
- HTML `data-*` атрибуты (`data-objects`, `data-points`, `data-shops`, `data-stores`, `data-features`)
- JSON-строки внутри `JSON.parse(...)`
- массивы и объекты, похожие на `shops`, `stores`, `points`, `markers`, `features`
- GeoJSON-подобные структуры
- DOM после рендеринга через резервный сценарий Playwright

Это означает, что источник в проекте обрабатывается не как один стабильный API, а как набор возможных представлений одних и тех же данных.

## 3. Параметры запросов и доступ

- Аутентификация: в текущей реализации не используется.
- Токены доступа: в текущей реализации не используются.
- Общие заголовки: запросы идут через `HttpClient` с браузерным заголовком `User-Agent`.
- Специальные заголовки: не используются.
- Cookies: используются только для обхода age-gate 18+.
- Proxy-поддержка: отдельная настройка proxy в проекте не реализована.
- Обработка 18+: реализована и в сценарии обычных HTTP-запросов, и в резервном сценарии через Playwright.

Для обхода 18+ в сценарии обычных HTTP-запросов код устанавливает cookies со значениями:

- `is_adult=1`
- `adult=1`
- `age_verified=1`
- `confirm18=1`
- `age=18`

Аналогичные cookies подставляются и в Playwright-контекст до открытия страницы.

## 4. Защита и ограничения источника

- Age-gate 18+ явно учтен в коде и обрабатывается отдельной логикой.
- Явных признаков CAPTCHA в текущей реализации не зафиксировано.
- Отдельной логики обхода блокировок по IP, VPN или по `User-Agent` в коде нет.
- Для статусов `429`, `500`, `502`, `503`, `504` действует общий механизм повторных попыток в `HttpClient`.
- Источник зависит от динамических данных карты и JavaScript, поэтому при изменении структуры страницы путь на обычных HTTP-запросах может перестать быть достаточным.
- На этот случай реализован резервный сценарий через Playwright, но он не гарантирует успех при полном изменении фронтенда источника.
- Если страница карты не загрузилась даже после попытки age-bypass, парсер возвращает пустой результат, а не аварийно завершает весь процесс.

## 5. Способ получения данных

Фактический алгоритм парсинга:

1. Загрузить страницу карты магазинов.
2. Проверить, не попали ли мы на age-gate 18+.
3. Если age-gate найден, установить подтверждающие cookies и повторить загрузку.
4. Попытаться извлечь магазины из встроенного JavaScript.
5. Если это не удалось, пройтись по внешним JavaScript-файлам, найденным на странице.
6. Если и это не дало результата, проверить HTML `data-*` атрибуты.
7. Если путь на обычных HTTP-запросах не сработал, перейти к резервному сценарию через Playwright.
8. В Playwright:
   - открыть страницу карты
   - предварительно подставить подтверждающие cookies
   - попытаться нажать на элементы подтверждения возраста
   - дождаться стабилизации страницы
   - вытащить массив объектов из `window`
9. Нормализовать сырые записи в `StoreRecord`.
10. Выполнить дедупликацию кандидатов и финальных нормализованных магазинов.

В проекте не реализованы обход карты через увеличение масштаба, клик по кластерам или фильтры интерфейса из исходного ТЗ. Вместо этого используется извлечение уже доступных данных из HTML/JS и общий резервный сценарий через Playwright.

## 6. Доступные поля

### Основные поля

Наиболее устойчиво в текущей реализации заполняются:

- `network`
- `source_url`
- `address` — если он присутствует в JS/HTML-данных
- `work_time` — если он присутствует в структуре данных или popup-данных

### Поля, заполняемые по возможности

Заполняются только при наличии подходящих данных в источнике:

- `city`
- `region`
- `latitude`
- `longitude`
- `phone`
- `store_format`
- `status`

## 7. Ограничения по данным

- `region` часто отсутствует или выражен слишком косвенно, поэтому нередко остается `null`.
- `city` иногда приходится выделять из объединенной адресной строки; если разделение ненадежно, поле не заполняется.
- `store_format` и `status` доступны только если соответствующие поля реально есть в JS, popup-контенте или свойствах объекта.
- Координаты могут отсутствовать у части объектов.
- В источнике могут встречаться дублирующиеся или конфликтующие карточки одной и той же точки.
- Структура JavaScript-переменных и HTML карты может меняться без предупреждения.

## 8. Стратегия устойчивости

Реально реализованные механизмы устойчивости:

- общий механизм повторных попыток `HttpClient`
- настраиваемый таймаут через `STORE_PARSER_TIMEOUT`
- настраиваемое количество повторных попыток через `STORE_PARSER_RETRIES`
- браузерный заголовок `User-Agent`
- обход age-gate через cookies в сценарии обычных HTTP-запросов
- обход age-gate через cookies и селекторы подтверждения в Playwright
- многоступенчатый резервный порядок:
  1. встроенный JavaScript
  2. внешний JavaScript
  3. HTML `data-*`
  4. Playwright
- warning/error логирование без падения всего процесса на первом проблемном объекте
- пропуск отдельных невалидных записей при нормализации
- дедупликация сырых кандидатов
- дедупликация финальных `StoreRecord` с выбором более полной записи
- корректная обработка пустого результата: если источник недоступен или обход age-gate не помог, парсер возвращает пустой список

Дополнительные задержки в коде есть только внутри Playwright-сценария:

- ожидание `networkidle`
- `wait_for_timeout(3000)` после загрузки страницы
- короткие паузы после попытки подтвердить возраст
